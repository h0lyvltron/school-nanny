# Competitor research (brainstorming)

Purpose: discover what kinds of capabilities similar products advertise, then
decide which ones are worth imagining as **our own** implementations—and whether
School Nanny’s overall set can compete on philosophy (self-hosted / family-owned
data, adult + kids, curriculum as data) as well as features.

## Prior research already on hand

- Well-Trained Mind forum mention spreadsheet (2008–2020 discussion frequency):
  summary in [`wtm-forum-sheet.md`](wtm-forum-sheet.md); CSV extracts alongside.
  Spreadsheet:
  https://docs.google.com/spreadsheets/d/1SroV3KdUshFIQMOEKfVDtv5zwmcylL6OHfewTuaeJRo/edit?usp=sharing

## Method

1. **Search for leads** — web search for commercial products *and* public GitHub
   / self-hosted repos.
2. **Record leads** in [`leads.md`](leads.md) (name, URL, why it showed up).
3. **Open-source peers** — skim README/feature lists into
   [`opensource.md`](opensource.md) (architecture ideas; not code copying).
4. **Fill [`matrix.md`](matrix.md)** by hand from public marketing claims,
   roundups, and OSS README claims—not verified product audits.
5. Turn gaps into a prioritized [`ideas.md`](ideas.md) backlog for us.
6. **User temperature** — skim forum threads (and echoing reviews) for desires /
   frustrations in [`user-temperature.md`](user-temperature.md).
7. Fold matrix + temperature into tangible product features in
   [`docs/PRODUCT_ROADMAP.md`](../../docs/PRODUCT_ROADMAP.md).

## What we do / don’t do

- **Do:** use search engines to find names, marketing URLs, and public repos;
  skim public claims and README feature lists.
- **Don’t:** crawl or bulk-download competitor sites, log into their apps, dump
  marketplaces, reuse their logos/copy in our marketing, or vendor their
  application code into School Nanny.

Claims in the matrix mean “advertises this,” not “we confirmed it works.”
